### 测试分层

本项目的测试按"验证成本"分三层，覆盖不同的失效模式：

| 层次 | 手段 | 能发现什么 |
| --- | --- | --- |
| **纯逻辑单元测试** | 直接调用领域函数 | 计算错误、边界条件、格式转义 |
| **数据集成测试** | 真实 SQLite 临时库 | 持久化往返、schema 迁移 |
| **UI 交互测试** | 真实 Compose 组件树 + 语义树点击 | 手势冲突、状态竞争、布局裁剪 |

> 第三层是投入最大的部分（占总耗时 95% 以上）。之所以需要它：
> 本项目多个棘手 bug 都属于"状态与手势交互"类，**纯逻辑测试无法复现**
> —— 例如「翻到未来月份后点击某天会退回旧月份」，所有状态模型组合都通过，
> 问题出在真实组件树的手势与重组时序上。

### 2.3 领域逻辑覆盖的内容

| 主题 | 覆盖要点 |
| --- | --- |
| **日历网格** | 月视图固定 42 格、周一起始对齐、周/日视图行数与月视图一致 |
| **周数计算** | ISO-8601 规则、跨年边界（第 1 周 / 第 53 周） |
| **农历与节气** | 春节为正月初一、节气仅在当天显示、闰月不加重复「闰」字 |
| **节假日** | 放假（休）与调休（班）区分、越界年份降级为普通日不抛异常 |
| **标签** | 归一化（去重、去空、长度限制）、存储格式往返 |
| **优先级** | 等级映射、排序（优先级降序 + 创建时间升序） |
| **完成统计** | 只统计未完成项、最高优先级着色 |
| **导出格式** | JSON 转义（含 U+2028/2029 与控制字符）、CSV 的 RFC 4180 转义（逗号/引号/换行） |
| **路径推断** | jpackage 两端布局差异（Linux 上溯两级、Windows 一级） |
| **自启动项内容** | `NoDisplay=false`、`Exec` 不加引号、必要字段齐全 |
| **持久化** | 关闭重开后数据读回、schema 幂等迁移（补列不丢数据） |

## 三、关键回归测试（针对实际发生过的 bug）

这些测试都是**先出现真实缺陷、修复后补上**的，用于防止复发：

| 缺陷 | 测试 | 说明 |
| --- | --- | --- |
| 翻页后点击某天会退回旧月份 | RandomClickAfterPagingTest、TodayClickRegressionTest、AnchorMonthInvariantTest | 用户多次反馈的严重问题。修复方式是在刷新时强制维持「锚点与选中日同月」的不变式，测试用随机点击与穷举验证 |
| 顶部日期与网格选中项不同步 | StaleAnchorRegressionTest | 锚点持有陈旧值 |
| 网格复用导致点击落到错误日期 | GridReuseClickTest | `LazyGrid` 复用单元格时的状态残留 |
| 详情弹窗删「本周其余安排」绕过确认框 | *（已人工验证，见第六节）* | 确定性 bug，表现为"有时不弹确认框" |
| 麒麟开机自启动静默失效 | AutoStartPathTest | 根因是 `NoDisplay=true`；因**失败无任何提示**，故用测试锁定 |
| 打包产物启动即崩（缺 `java.sql` 模块） | *（由构建验证发现）* | jlink 裁剪掉了 `java.sql`，构造仓库时抛 `NoClassDefFoundError` |
| Windows 报「Failed to launch JVM」 | *（由日志定位）* | 启动画面渲染在 `application {}` 作用域，缺窗口级 CompositionLocal 而崩溃 |

### 一个被证伪的假设（记录在案）

`StaleClosureTestMetaTest` 记录了一次**失败的假设**：曾怀疑"点击落错日期"
是 `Modifier.pointerInput` 捕获了旧的 lambda（陈旧闭包），
但用一个"对照组"测试证明 —— 旧写法同样能读到最新值。
假设被证伪后改动已回退，测试作为记录保留。

> 保留这类测试的意义：避免后来者重复走同一条弯路。

## 五、构建产物验证

每次发布都对最终产物做校验，确保"本地构建的"与"用户下载到的"完全一致。

| 验证项 | 方法 | 结果 |
| --- | --- | --- |
| 产物存在且体积合理 | 检查文件大小 | ✅ |
| 完整性 | 本地 SHA256 vs GitHub 记录的 digest | ✅ 一致 |
| 可下载性 | 匿名 HTTP 请求（不带 token） | ✅ `HTTP 200`，字节数吻合 |
| 完整下载校验 | 下载全文件后比对字节数与 SHA256 | ✅ 一致 |
| `.deb` 安装布局 | WSL 解包检查目录结构与运行时模块 | ✅ 含 `java.sql` 等必需模块 |
| `.deb` 元信息 | `dpkg-deb --info` | ✅ 包名、版本、架构正确 |
| 应用镜像内 jar | 哈希比对（确认每次打包都重新构建） | ✅ |

> 确认修复确实进入了安装包。

## 六、性能验证

### 6.1 内存（实测）

| 场景 | 工作集 | 私有内存 |
| --- | --- | --- |
| 硬件渲染（默认） | 361 MB | 682 MB |
| **软件渲染（省内存模式）** | **215 MB** | 482 MB |

**降低约 40%**，已做成设置项供低配机器选用。

诊断过程：最初想直接调 `-Xmx`，但先在日志里加了内存构成记录，
实测发现 **JVM 自身只占 33MB（堆 19MB + 非堆 14MB）**，
而进程整体 361MB —— 说明大头在 **Skia 渲染引擎的 native 内存**，
JVM 参数管不到。据此才转向渲染方式。

同时补充了 JVM 参数优化（限制堆上限、Serial GC 替代 G1、
限制 Metaspace / Code Cache / JIT 线程数）。

### 6.2 启动

| 项 | 情况 |
| --- | --- |
| 冷启动 ≤ 2 秒（需求指标） | ❌ **未达标**。JVM + Skia 初始化本身需数秒 |
| 感知优化 | ✅ 启动画面立即显示；数据库连接移入后台线程，避免"点了没反应" |
| 多实例 | ✅ 单实例守卫（文件锁），多次点击不再开出多个窗口 |

### 6.3 操作响应

待办数量级很小，增删改查均为本地 SQLite 单条操作；
日历整页（42 天）的待办统计用**一次区间查询**取得，而非逐格查库。
需求 4.2 的 100ms 指标在实际使用中未见异常。

## 八、结论

- **207 个自动化测试全部通过**，覆盖领域计算、数据持久化与真实 UI 交互三个层次
- 历史上出现的**主要缺陷均已补上回归测试**，其中"翻页后点击跳错月份"
  这一类最难复现的问题，用随机点击与穷举点击做了较强覆盖
- Windows 与银河麒麟 V10 **双平台人工验收通过**（含中文输入法）
- 构建产物经**匿名下载与 SHA256 双重校验**，确认用户拿到与开发构建一致
- **主要短板**：冷启动速度未达需求指标、ARM64 未构建、部分项仅单机验证
  （详见第七节）
